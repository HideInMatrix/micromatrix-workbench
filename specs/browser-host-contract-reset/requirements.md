# 浏览器观察与 Host 可靠性：需求

状态：设计提案；本轮不修改运行代码。
基线：a80e72f；输入为用户的 DB-015A / DB-015B 实测汇总及本地源码审查。

## 目标与范围

AI 通过 Workbench 收到真实界面图像与必要结构化信息，决定下一步动作，执行后再次观察。Workbench 提供能力、权限和状态，不承担模型决策。

本轮修复公开工具契约、Browser/CDP 观察闭环、Host 故障隔离和恢复、Runtime 本地工具解析。通用桌面后端后续复用这些边界。本轮不新增桌面控制、浏览器扩展、通用插件装载框架或独立 Computer Use MCP 服务。

用户故事：
- AI 客户端能直接调用目录列出的工具，不通过临时 Workflow 绕行。
- 用户停止或重启失效的 Host 执行进程时，已经运行的 Runtime 和本地工具继续工作。
- AI 能区分工具未暴露、Host 不在线、等待用户授权和操作本身失败。
- 维护者只维护一份公开工具定义，不增加旧名字转发、新旧字段兜底和双套分发。

## 可验证要求

- R1：当客户端读取 Catalog 时，每个 invocation 的目标必须出现在同一客户端、同一契约版本的 tools/list 中；参数必须符合目标 schema。技能和工作流作为组合能力列出时，也必须指向真实公共入口。
- R2：当内部方法未作为公共工具注册时，系统不得把它标记为可直接 MCP 调用；工作流执行使用同一公共工具注册表。
- R3：当 Host 不在线时，Host 能力调用在总计 1 秒内返回 HOST_DISCONNECTED。已知失联不进入原有 30 秒轮询；状态查询不调用失效 Worker。
- R4：当 Host 心跳仍新鲜但突然卡死时，请求确认阶段也必须有小于 1 秒的独立上限；不得把旧心跳当作执行线程可用的证明。
- R5：当可独立重启的 Host Worker 恢复时，原 Runtime 重新握手并能创建新 Browser session；旧会话返回 SESSION_EXPIRED，不静默恢复或重放动作。
- R6：当 Host 离线且已注册工具的文件指纹、执行范围和项目绑定仍有效时，Node/Git/Python 等工具按注册入口执行，不等待 Host。
- R7：当工具注册已过期或项目版本约束改变时，系统明确报告失效，不能偷偷换用 PATH 中的其他版本。
- R8：当 Browser status/snapshot/screenshot 被调用时，声明与执行所需权限一致；纯观察不要求文件写权限。截图显式保存时才检查工作区写权限。
- R9：当用户只授予 Browser 权限时，该授权不能扩展为任意桌面应用控制、Host Identity 或 Host 重启权限。
- R10：当浏览器观察成功时，调用方直接收到标准 MCP image 内容、会话与页面信息；不要求再调用 view_image 才能看到截图。
- R11：当动作后观察失败时，结果分别说明动作是否已执行、观察是否成功；不得把执行过的点击作为可安全重试的动作。
- R12：当 Host 请求失败时，错误携带 request_id、generation、stage、cause_code 及已知时间点；未知时间点为 null，绝不伪造 OS 拒绝原因。
- R13：当操作已知被工作区边界或 OS 权限阻止时，系统返回准确原因与可行下一步；应用内授权不声称能够突破 OS sandbox。可行性无法预判时明确 unknown，执行失败仍分层报告。
- R14：当进程退出非零、被取消或超时时，返回明确失败状态；运行中的进程不宣称已成功完成。工作流与结果摘要使用同一语义。
- R15：当 Host generation 失效或临时会话到期时，清理只作用于 Workbench 所有的资源，不终止用户原有应用，不删除活跃会话目录。
- R16：当读取 server_info 时，默认返回版本、契约版本和摘要；详细工具与诊断通过定向查询获取，不触发工具探测或 Host 网络往返。
- R17：当发布新契约时，项目内所有调用方和已知持久化引用必须完成离线校验与一次性迁移；运行时不保留别名、双入口、旧协议 fallback 或创建 Workflow 的修复逻辑。

## 验收边界

“Host 恢复”指独立 Host Worker 的崩溃、挂起和重启。当前 Desktop UI 正常退出会停止全部服务，这是另一个产品行为；本轮不把正常退出改成后台常驻。

Worker 重启后保证工具再次可用，不能保证已死亡浏览器的页面、登录状态或未完成动作自动恢复。整个 Desktop/Supervisor 都退出后的无人值守常驻恢复，需要额外的进程所有权设计，不属于本轮承诺。

测试包括正常浏览器闭环、断开前后各状态、Host 卡死与崩溃、同 Runtime 恢复、Runtime 工具离线可用、权限隔离和 Catalog 不变量。DB-015B 应不再需要临时 workspace workflow。
